# 0002 更新批次用 Synthea 快照產生

- 狀態：accepted（2026-10-16）

## 背景

增量處理需要「同一個 id、內容不同」的多批資料，才能驗證「取最新」和「只更新有變的」。原本的構想是用不同的種子產第二批。

用 3 個病人實驗的結果：

| 做法 | 和第一批相同的 id |
|---|---|
| 換種子（42 → 43） | 四種資源都是 0 筆 |
| 存快照、往後模擬 180 天 | Patient 3/3 同 id 且內容有變；Encounter 282 筆相同、4 筆新增、48 筆未出現 |

另外發現：同樣的 `-s` 和 `-r` 重跑，如果沒有固定 `-cs`（醫師種子），Encounter 的 `participant` 每次都不一樣。

## 選項

- **A. 換種子**：每批一群全新的病人。
- **B. 快照接續**：第一批存快照，之後每批載入上一批的快照，往後模擬一段時間，再存新快照。
- **C. 手工修改**：複製第一批，用程式改幾筆內容當第二批。

## 決定

選 B，共 4 批，模擬每月更新：

| 批次 | 產生方式 |
|---|---|
| `batch_001`（初始批次） | `-p 1000 -s 42 -cs 42 -r 20261013`，用 `-u` 存快照 |
| `batch_002` ~ `batch_004`（更新批次） | `-s 42 -cs 42`，用 `-i` 載入上一批快照，`-t 30` 往後 30 天，再用 `-u` 存新快照 |

某個 id 在後來的批次**未出現，不視為刪除**。刪除留到第二階段，用刪除清單或 `entered-in-error` 狀態明確模擬。

## 理由

- A 測不到任何版本比較，只會測到新增。
- B 的變動是 Synthea 模擬出來的（病情緩解、新的就診），比 C 手工改的更接近真實的來源更新。
- 固定 `-cs 42` 之後，同樣參數重跑的輸出完全相同，資料可以重現。
- Synthea 預設只匯出最近 10 年（`exporter.years_of_history = 10`），時間往後推，最舊的資料就會掉出範圍。所以「未出現」只是匯出範圍改變，不能解讀成刪除。

## 後果

- 快照約每人 3MB，1000 人一份約 3.5GB，4 份約 14GB，只能放本機，不進 Git。
- 改了任何一批的參數，後面的批次都要從那一批開始依序重新產生。
- 現有 `output/` 那一批產生時沒有存快照，要用新參數重新產生。
- 30 天的變動量小：6 個病人的實驗中，一個月只有 4 筆 Condition 有變、3 筆新增。1000 人預估每批有數百筆變動。
