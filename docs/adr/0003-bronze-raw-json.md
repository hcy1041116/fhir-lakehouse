# 0003 Bronze 保存原始 JSON 字串

- 狀態：accepted（2026-10-16）

## 背景

範圍要求 Bronze 把 NDJSON「原樣」寫成 Delta 表。「原樣」可以有兩種理解：保存原始文字，或是保存解析後的巢狀結構。

## 選項

- **A. 原始字串**：每一行存成一個文字欄位，旁邊加上 id、批次、來源檔、行號、載入時間。到 Silver 才用明確定義的 schema 解析。
- **B. 自動推斷結構**：讓 Spark 讀 JSON 時自動推斷 schema，存成巢狀欄位。

## 決定

選 A。

## 理由

- A 是真正的原樣，任何時候都能從 Bronze 重新產生 Silver，不受當初解析方式影響。
- 來源多了新欄位，A 也不會寫入失敗；B 每一批推斷出來的結構可能不同，結構不合就寫不進去。
- B 推斷 schema 需要多讀一次資料，Observation 一批就有 600MB。
- A 搭配明確的 schema，等於把「我們用到哪些欄位」寫成清楚的規格。

## 後果

- 直接查 Bronze 不方便，要先解析。這是可以接受的，因為分析是在 Silver 和 Gold 做。
- 每種資源都要維護一份明確的 schema，只列出 Silver 用到的欄位。
- JSON 格式錯誤的那一行照樣存進 Bronze，到 Silver 才由品質規則擋下。這樣 Bronze 的筆數才能和來源檔的行數完全相符。
